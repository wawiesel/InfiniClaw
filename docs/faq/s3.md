# S3 FAQ — Backup and Bot Transport

## Overview

InfiniClaw uses a self-hosted **MinIO** server (S3-compatible object storage) for backing up bot conversation state. It runs in Docker on the host machine and is accessible both locally and externally.

## Infrastructure

| Component | Details |
|-----------|---------|
| Server | MinIO in Docker, port 9000 |
| External URL | `s3.a-gis.org` (NAS reverse proxy) |
| Local URL | `http://localhost:9000` |
| Bucket | `infiniclaw` |
| Config | `~/.config/infiniclaw/machine.json` → `s3` section |

## What Gets Backed Up

Each bot stores state under `infiniclaw/{bot}/`:

| Path | Contents |
|------|----------|
| `store/messages.db` | SQLite — Matrix messages, sessions, scheduled tasks, router state |
| `store/matrix-bot.json` | Matrix sync token (resume position) |
| `data/sessions/` | Claude Code session JSONL files (AI conversation transcripts) |

There is one copy per bot (latest snapshot, no versioning). Each push overwrites the previous.

## When Sync Happens

| Event | Direction | Blocking? |
|-------|-----------|-----------|
| `cli stop` | Push (local -> S3) | No — runs in background |
| `cli sync push` | Push (local -> S3) | Yes |
| `cli sync pull` | Pull (S3 -> local) | Yes |
| `cli start` | Nothing | N/A — no auto-pull |

**Push is automatic on stop.** The stop command returns immediately; the S3 upload runs in the background.

**Pull is manual only.** It overwrites local files without merging. Use it only when transporting a bot to a new machine.

## Bot Transport Workflow

To move a bot from machine A to machine B:

1. On machine A: `npm run cli stop <bot>` (waits for background push to complete)
2. On machine B: Add bot to `machine.json`, set up secrets
3. On machine B: `npm run cli sync pull` (downloads state from S3)
4. On machine B: `npm run cli start <bot>`

## Configuration

In `~/.config/infiniclaw/machine.json`:

```json
{
  "s3": {
    "endpoint": "http://localhost:9000",
    "bucket": "infiniclaw",
    "accessKey": "minioadmin",
    "secretKey": "<secret>"
  }
}
```

If the `s3` key is absent, all sync operations are silently skipped.
